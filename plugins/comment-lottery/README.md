# 评论抽奖

为 Simple PHP Blog（SBlog）文章添加评论抽奖模块。使用原有插件接口实现，不需要修改核心或主题。支持起止时间、中奖名额、自动开奖、中奖评论公示及站点邮件通知。

## 安装与使用

1. 将整个 `comment-lottery` 文件夹放到站点 `plugins/` 中，在后台「插件管理」启用「评论抽奖」。
2. 打开文章编辑器，点击正文编辑工具栏中的转盘图标（悬停提示「评论抽奖」），填写标题、活动说明、开始时间、结束时间和中奖名额。
3. 选择是否按邮箱去重、只允许顶层评论、自动开奖和中奖邮件通知，插入模块后保存文章。时间统一采用北京时间 `Asia/Shanghai`。
4. 发布文章，让读者在该文章的评论区参与。活动结果会在文章内的抽奖模块公示。
5. 在「插件管理 → 评论抽奖 → 设置」查看活动、中奖名单、邮件状态及自动开奖任务配置。手动开奖只能在结束时间之后执行。

模块创建后必须保存到文章，且文章已经公开发布、正文仍包含对应模块，才会开奖。草稿、尚未到发布时间的文章以及模块已移除的活动不进行自动开奖。需要暂停活动时可移除模块并保存；恢复原模块后继续按原活动规则处理。已经开奖的名单保持固定，不能通过重复请求重新抽取。

## 参与规则

- 评论必须属于当前文章，提交时间位于 `[开始时间, 结束时间)`；结束时间当刻提交的评论不参与。
- 只抽取开奖时已经审核通过的评论；待审、垃圾评论及管理员登录发表的评论不参与。
- 评论必须具有有效邮箱。邮箱只用于确定参与身份和发送中奖通知，不会在公开的中奖名单中展示。
- 默认每个邮箱一次机会：不区分邮箱大小写，同一邮箱只保留最早一条符合条件的评论，时间相同则按评论 ID 排序。
- 关闭邮箱去重后，每条符合条件的评论均可参与，同一人可能凭多条评论多次中奖。
- 「仅顶层评论」开启时，回复评论不参与；关闭时，顶层评论和回复都可参与。
- 使用服务器安全随机数无放回抽取评论。候选数不足时按实际候选数开奖；没有候选评论时活动结束且没有中奖者。

每篇文章同时启用一个抽奖模块；短代码需独占一段，不能放在代码块内。已发布文章的活动开始后，规则即锁定；草稿中的活动仍可编辑。修改未开始活动会立即保存配置，首次插入必须再保存文章才能生效。举办下一轮活动时，先移除旧模块并保存文章，再插入新活动。

开奖时保存中奖评论快照，后续修改或删除评论不会改变已经确定的中奖名单。已删除或撤回审核的中奖评论会隐藏公开昵称和正文，但保留中奖记录。自动开奖由下述任务或站点访问触发。

## 中奖邮件通知

抽奖插件调用核心 `send_site_mail()`，复用现有的「邮件通知」插件，不另存 SMTP 密码。当前环境如未安装该插件，管理页会提示安装；抽奖插件不会自动安装或启用它。

在扩展商店安装「邮件通知」，在插件管理中启用并进入其设置。启用 SMTP，按邮件服务商说明填写主机、端口、加密方式、账号、授权码和发件邮箱，常见组合是 SSL / 465 或 TLS / 587。该插件的「通知收件邮箱」用于管理员的新评论通知，中奖通知始终发送到中奖评论留下的邮箱。

邮件失败不影响开奖或中奖公示。每次运行最多处理 20 封邮件，失败邮件至少间隔 5 分钟自动重试，最多自动尝试 5 次。可在抽奖管理的活动详情中手动重试未成功的通知。SMTP 或 PHP mail 返回成功仅表示发送接口接受，并不保证最终投递，请结合邮件服务商日志确认。

若 PHP 在发送过程中超时或中断，邮件可能已经发出而状态仍为「发送中／结果待确认」。这种情况不会自动重试；至少等待 10 分钟，确认原请求不再运行并查看服务商日志，然后在后台勾选确认后手动重试。手动重试可能造成重复邮件。

## 到期自动开奖

活动勾选「自动开奖」后，站点访问会补做已经到期的开奖。没有访客时 PHP 不会自行常驻运行，因此要在到期后自动处理，应配置每分钟运行一次的服务器计划任务。正常延迟由执行周期和积压情况决定，不保证在结束时间的同一秒触发。未勾选自动开奖的活动只接受后台手动开奖。

先在站点设置中填好实际站点地址；进入评论抽奖管理页，复制已生成的「任务地址」和「任务密钥」。地址应是实际域名下的 `index.php?a=lottery_tick` 路由，不能使用临时域名或仅本机可访问的地址。

任务请求必须使用 POST，密钥放在 `X-SBlog-Lottery-Key` 请求头中。不要把密钥添加到 URL 查询参数。管理页仅对管理员开放且禁止缓存；任务密钥应只保存在服务器任务配置中。更换任务密钥后旧密钥立即失效，必须更新服务器任务。

### Linux / 宝塔

管理页直接生成含实际 URL 和密钥的完整命令。Linux 执行 `crontab -e` 后添加该整行，格式如下；将示例占位值替换成管理页的实际值：

```cron
* * * * * curl --fail --silent --show-error -X POST -H 'X-SBlog-Lottery-Key: KEY' 'URL'
```

宝塔计划任务选择「Shell 脚本」、每分钟执行，脚本内容使用管理页命令去掉开头五个星号后的 `curl` 部分。

### Windows 任务计划程序

附带的 `cron-example.ps1` 只执行一次，不会创建或修改系统计划任务。管理页生成该站点的完整调用命令，在 PowerShell 中也可以执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\站点目录\plugins\comment-lottery\cron-example.ps1" -WorkerUrl "URL" -WorkerKey "KEY"
```

在「任务计划程序」中新建任务：

1. 程序填写 `powershell.exe`，参数填写上面从 `-NoProfile` 开始的部分，并替换为实际脚本绝对路径、URL 和密钥。
2. 设置每天触发，勾选每 1 分钟重复，持续 1 天；选择「不管用户是否登录都要运行」，并使用可读取脚本及访问站点的账号。
3. 在任务的设置中选择「如果任务已运行，则不启动新实例」。
4. 手动运行一次任务，在抽奖管理页检查「最近运行」是否更新，再按任务日志排查网络或授权错误。

脚本通过 `Invoke-RestMethod` 发送 POST 请求，密钥仅在请求头中传输。脚本不会把密钥写入输出，任务命令本身仍应只允许服务器管理员查看。

每次最多处理 20 个到期活动及 20 封邮件；积压在后续运行中继续处理。开奖在数据库事务中固定结果，并发访问和重复计划任务不会重复抽取同一活动。

## 注意事项

- PHP、数据库和插件目录需保持正常可用；服务器计划任务应能访问配置的站点 URL。
- 文章内模块的参与条件以保存后的配置为准；先插入但未保存的模块不会开始开奖。
- 关闭抽奖插件后自动处理与模块渲染停止；重新启用时保留已有活动和中奖结果。
- 使用静态页面缓存时，插件会协调活动页面及开奖结果的缓存更新；外部 CDN 或反向代理另有缓存时，需要按站点部署规则刷新。
- 邮件通知及服务器任务需要管理员自行配置，安装本插件不会自动发送测试邮件或创建系统任务。
